# Live-operations telemetry, 2026-10-19 — NOT a benchmark

Source: production agent traffic (parallel coding agents via LiteLLM) against
the OrcaRouter container running the NVFP4-KV branch-aligned serving profile
(luni-llmops-linux main `f803eb1`). Values below are **opportunistic operating
statistics mined from the server log**, not controlled benchmark points:
prompt shapes, sharing, and arrival times are uncontrolled, per-concurrency
sample counts are uneven, and each row mixes different users. Do not average
them with or substitute them for the seeded `bench-results/` matrices.

Deployed profile (verified via `/server_info`): kv-cache nvfp4, pool
1,499,968 tokens (page-64-aligned form of 1.5M), mem-fraction 0.98, running
16 / queued 16, chunked-prefill 2048, prefill-decode interval 1, fixed NEXTN
3/4 (topk 1), mamba cache 48 + max-states-per-path 5, cuda graphs bs<=16,
NVMe PLE, HiCache off, loopback only.

## Prefill throughput

1,934 cache-miss prefill lines: median **1,962 tok/s**, p90 3,585, max 7,293
(chunk-capped at 2,048 tokens per batch). Cache-hit continuations stream as
small remainder chunks and are excluded.

## Cache occupancy during real work

`sglang:token_usage` peaked at **0.54** of the 1,499,968-token pool (~810k
tokens; 0.43 at sampling time), mamba usage peak 0.71 of 48 slots. The 1.5M
pool is not yet pressured by agent fleet load.

## Reference comparison (different harnesses — directional only)

| source | c1 | c4 | c8 |
|---|---:|---:|---:|
| branch reference (SparkDash prose, 400 out, controlled) | 258 | 608 | 818 |
| Oct-12/17 local recipe (controlled, chunk 8192 + adaptive + skip-lock) | ~160 | ~242 | 320-400 |
| today, live ops (this doc, uncontrolled) | 129 | 300 | 307 |

Conclusion for branch owners: interval-1 prefill interleaving costs decode
throughput on cache-miss-heavy agent traffic (observed c1 -50% vs branch
reference; c3+ recover because prefills amortize), while the NVFP4-KV branch
profile holds the 1.5M-token pool requirement and stays healthy. Candidates
to close the c1 gap without losing the branch profile: relax
`--prefill-decode-interval` (>1) and/or adaptive NEXTN widths; recommend one
controlled A/B point before flipping the standing profile.
